## 1. 产品定位与原则

Self Study Studio 是极简的 AI 辅助自学项目内容进度管理工具，帮助用户知道一个项目学到了哪里、接下来学什么。

- 只跟踪学习内容的完成进度，不管理学习时间。
- AI 只降低初始化成本，不参与日常进度维护或教学。
- 「学习计划」仅指学习内容的组织与顺序，不包含每日任务、学习周期或截止日期。
- 尽可能减少输入和操作：创建时只必填项目名称，日常主要操作是标记完成。
- 内容完成由用户判断，不等于知识掌握，不要求笔记、证据、测验或复盘。
- 主要页面只有首页和项目详情；创建、预览和编辑通过附属流程完成。

典型场景：输入「学习 React」，确认 AI 生成的内容列表；学完一个单元后点一下完成；再次打开项目时从首个未完成单元继续。

## 2. 核心实体与规则

### 2.1 Project：学习项目

| 属性 | 产品含义 |
| --- | --- |
| 标识 | 唯一标识项目，用于关联学习单元 |
| 名称 | 必填，如「学习 React」 |
| 暂停状态 | 支持暂停与恢复；不改变已有单元和完成进度 |
| 可选学习资料 | 创建时提供的课程链接或目录，供 AI 初始化使用 |

项目包含有序的 LearningUnit 列表。完成比例、当前单元、下一单元和「全部完成」均由列表推导，不要求用户额外维护。

### 2.2 LearningUnit：学习单元

学习单元是一项可独立标记完成的内容，例如一节课程、一个章节或一个主题。首版采用单层有序列表，不引入阶段、子任务或多层目录实体。

| 属性 | 产品含义 |
| --- | --- |
| 标识与所属项目 | 唯一标识单元并关联 Project |
| 标题 | 简洁描述学习内容，不能为空 |
| 顺序 | 决定列表展示与继续学习位置 |
| 完成状态 | 未完成 / 已完成；新单元默认为未完成 |
| 完成时间 | 标记完成时自动记录，未完成时为空；用户无需填写 |

完成时间仅为状态元数据，不用于时长计算、打卡、连续学习天数或时间安排。

### 2.3 进度计算

```text
总单元数 = 项目当前列表中的单元数量
已完成单元数 = 当前列表中完成状态为已完成的数量
完成率 = 已完成单元数 / 总单元数
```

所有单元等权，不按时长、难度或内容长度加权。界面同时显示「已完成数 / 总数」和百分比。

为便于实施，本版采用以下边界规则：

- 没有单元时显示「尚无学习单元」和 0%，不执行除零计算，不判定为全部完成。
- 非空列表的所有单元完成后显示 100% 和「全部完成」，无需再次确认项目完成。
- 新增单元默认未完成；增删单元后按当前列表重新计算，完成率可能升高或降低。
- 重命名、排序不改变单元完成状态及完成时间；排序会更新继续学习位置。
- 允许取消完成以纠正误操作，取消时清空完成时间；再次完成时记录新的完成时间。
- 重复点击已完成操作不覆盖原完成时间；状态变化须保存并同步反映到首页与详情。

### 2.4 当前单元与下一单元

为避免另设「正在学习」状态，本版按内容顺序推导位置：

- 当前单元：有序列表中的第一个未完成单元，即打开项目时应继续的内容。
- 下一单元：当前单元之后的第一个未完成单元；不存在时显示「无下一单元」。
- 标记完成后重新计算；原下一单元成为当前单元，详情自动定位到新的当前单元。
- 支持用户完成任意单元，不强制按顺序；仍优先定位最靠前的未完成单元。
- 全部完成时当前、下一单元均为空，显示「全部完成」；空列表提示添加内容。
- 暂停时保留位置和进度，显示「已暂停」；恢复后继续原有内容，不重生成计划。

这些边界规则是对已确认方案的实施口径补充，不新增核心功能。

## 3. 四项核心功能

### 3.1 AI 生成初始内容结构

**输入：** 项目名称必填；课程链接或目录可选。不要求学习目标、学习周期、每日时长、截止日期或前置知识问卷。

**生成依据：** 优先根据用户提供且实际可读取的课程资料整理内容及顺序；没有资料时，根据主题生成建议结构，并明确标注「建议结构」。不能把主题推测伪装成真实课程目录。

**输出：** 有序的学习单元标题列表。输出不含时间排程、测验、教学内容、学习记录或掌握程度判断。

**确认流程：**

```text
首页创建项目 → 输入项目名称及可选资料 → AI 生成草稿
→ 预览 → 可修改 / 增删 / 排序 / 重新生成
→ 用户确认创建 → 保存 Project 与 LearningUnit → 项目详情
```

- 确认前仅为草稿，不计入已保存项目的进度；取消创建不保存正式项目。
- 重生成只作用于当前初始化草稿；已有手动编辑时，替换前应让用户明确知道编辑将被替换。
- 确认后 AI 不自动增删、重排、重命名内容，也不修改完成状态；后续调整由用户手动完成。
- 链接无法读取时如实提示，允许粘贴目录、重试或明确选择按主题生成；不声称已读取链接。
- AI 超时、失败或结果无效时保留输入和已有草稿，允许重试或手动建立内容列表。
- 不把任意课程网站抓取、付费内容访问或登录态读取作为首版承诺。

### 3.2 一键标记完成

用户在详情列表点击单元的完成控件，即更新状态、自动记录完成时间、重新计算项目进度，并定位新的当前单元。操作不要求填写笔记、时长、感想或完成检查。用户可以取消完成以纠正误操作。

暂停项目保留可查看、可编辑的内容；继续学习主操作先恢复项目，再定位当前单元，恢复不重置进度。

### 3.3 项目进度展示

首页和项目详情使用同一套推导规则，同时展示：

- 项目名称及暂停状态；
- 已完成单元数、总单元数与完成百分比；
- 当前单元和下一单元；
- 空列表、全部完成或已暂停的明确状态。

进度只描述内容完成情况，不展示学习时长、活跃天数、掌握程度或跨项目加权总分。

### 3.4 手动调整与暂停恢复

- 支持学习单元新增、删除、标题修改和排序。
- 删除单元前明确提示该单元及其完成状态将从当前列表移除，确认后重算进度。
- 调整未涉及的单元保留原标识、完成状态与完成时间。
- 支持项目暂停和恢复，不要求填写原因，不生成恢复计划或补学任务。
- 项目暂停不删除内容，不将未完成单元视为完成；暂停状态与完成比例分别展示。

## 4. 两个主要页面

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 首页 | 项目列表；每项显示进度、当前/下一单元和暂停状态 | 创建项目、进入项目继续学习 |
| 项目详情 | 项目进度、当前/下一单元、完整有序单元列表 | 一键完成、修改列表、暂停/恢复 |

创建与草稿预览采用首页内的附属流程；列表编辑放在项目详情中，不增加独立的计划管理中心。没有项目时首页只说明用途并提供「创建项目」入口；没有单元时详情提供「添加学习单元」入口。

日常流程：

```text
打开首页 → 进入项目 → 查看当前单元 → 在外部学习
→ 点击完成 → 进度更新并定位下一未完成单元
```

日常完成操作不触发 AI 请求，也不增加记录确认页。

## 5. 明确不在 MVP 范围内

| 类别 | 本版不包含 |
| --- | --- |
| 时间管理 | 学习计时、番茄钟、时长统计、每日任务、周期、截止日期、日历排程、提醒与补学安排 |
| 打卡与激励 | 连续学习天数、签到、排行榜、徽章和惩罚性提醒 |
| 笔记与记录 | 学习笔记、Session 日志、Proof 证据、附件库、学习轨迹、周报与复盘 |
| 教学与测评 | AI 导师、问答教学、练习生成、测验、完成检查、掌握程度评估 |
| 动态规划 | AI 日常建议、自动调整内容、计划版本审批、阶段与里程碑、多层任务树 |
| 平台扩展 | 社交、多人协作、公开课程市场、完整资源管理与通用课程爬虫 |

首发已确认 iPhone 与 Web 同期改版及跨端同步；账号、存储和旧数据兼容的实现决策见第 7 节关联方案。已有功能不会因本文更新而被自动删除；旧数据映射和迁移需要另行评估，不得默认把学习日志或证据直接换算为完成单元。

## 6. 验收标准

以下是待实现的验收要求，不代表本次已经执行功能验收。

1. 只输入项目名称即可发起 AI 初始化；课程资料可选，没有必填时间或目标字段。
2. 有可读目录时优先依据目录生成；无资料时标明建议结构；无法读取链接时如实反馈。
3. AI 结果可预览、编辑、增删、排序和重生成，确认前不保存为正式项目进度。
4. 用户确认后保存项目及有序单元；AI 后续不自动改变内容或完成状态。
5. 完成一个单元只需一次状态操作，自动写入完成时间，不要求额外记录；取消完成可纠错。
6. 例如 4 个单元完成 1 个，两个页面均显示 1/4、25%；再完成一个显示 2/4、50%。
7. 完成后定位首个未完成单元；乱序完成、重排、全部完成及空列表按第 2 节处理。
8. 增删单元会重算进度；修改标题、排序及暂停恢复不丢失其余单元的完成信息。
9. AI 失败不会丢失输入或已有草稿；手动调整和日常完成操作不依赖 AI 可用性。
10. 首页与项目详情覆盖主要使用流程，不出现时间、打卡、笔记、教学或复盘的必经步骤。
