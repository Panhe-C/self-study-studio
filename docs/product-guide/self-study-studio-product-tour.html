产品功能走查

把「我学了什么」变成「下一步做什么」

Self Study Studio 是给同时推进多个自学项目、又不想维护知识管理系统的人做的学习系统。 它的立场是证据先于活动：时长和频次只解释进度，真正让进度成立的是被接受的 Proof 和学习者自己做出的复盘决定。

产品决策
33 条 ADR

01产品只做一件事

其他所有功能都挂在这条链上。

关键立场

注意最后那个菱形。复盘产出的是建议，必须你点一下才生效。 产品从不自己改你的计划或状态，这个约束贯穿全部功能。

02四个 Tab，入口刻意少

实线是 Tab，虚线是从 Tab 里打开的流程。

Review、Learning Plan、Stage Review、Cloud Sync、AI 设置都不是独立 Tab， 它们从需要它们的地方进入。Web Workspace 另外提供明确标记的 Demo 与 Real 模式； Real 读写必须经过 C1/C2 合约，不会静默回退到 Demo。首次设置要求至少为第一个项目存下一条记录，Today 才开放。

03数据骨架

六个核心概念以及它们背后的实际记录类型。

两个容易搞混的地方。PLANNED_SESSION 和 SESSION 是两个不同的东西：前者是「计划要做」，后者是「实际做了」，完成计划时前者指向后者； Proof 挂在实际记录上，不挂在计划上。

另外，一个项目要变成 active，必须有 Goal、唯一 Next Step 和一份 EVIDENCE_CONTRACT。这是「证据优先」在代码里的强制点，不是一句口号。

04Today 怎么决定给你看什么

纯确定性排序，没有 AI，没有黑盒评分。

「最多 3 条」和「稳定打破平局」都有测试保护。产品刻意不做「今天做 12 件事」的清单， 因为一个做不完的清单只会让人关掉应用。

05两条记录路径，一种 Session

摩擦程度不同，落地成同一种记录。

如果这条 Session 是从某个计划会话启动的，保存时会原子地 把那个计划会话标记完成，不会出现「记录存了但计划没勾上」的中间态。

06Proof 的门槛

必须回答「这证明了什么」，否则存不下去。

为什么加这道摩擦

这是产品最有态度的设计，它拒绝变成附件仓库。一张截图加上「这证明我能独立推导反向传播」 才是 Proof；只有截图不是。

07从目标到计划

四步草稿，AI 没有权威。

两点值得强调。AI 的输出不点「激活」什么都不是；周预算超了只警告不拦， 因为产品认为「明知故犯地过载」是学习者的合法选择，不是需要被系统纠正的错误。

08三道互不越界的确认边界

如果只记一张图，记这张。

日历权限也不在启动时索要，必须你主动去设置里授权并选目标日历。同步给 iCloud 的 「忙碌时段」只有区间边界，不含事件标题、备注、参与人、地点。

内部日历在没有 iCloud、没有 AI 配置、没有网络、没有日历权限的情况下依然可用。 这不是降级体验，是设计目标。

09练习例程

和计划完成度解耦。

练习是「保持手感」，计划完成度是「推进阶段」。产品刻意不让前者冒充后者， 否则每天弹半小时琴就能刷出「课程完成 80%」的假象。

10复盘与 AI 降级

AI 不可用时闭环不断。

没配 AI、没网、返回的 JSON 解析失败，任何一种情况都落到本地规则复盘。 API Key 存 Keychain，Endpoint 和 Model 存偏好设置，两者的生命周期不同，所以分开放。

11同步与冲突

本地先落地；Web Real 的远端写入必须经过 typed contract、Revision Guard 与冲突工作区。

12数据主权

导出的是你的学习内容，不是应用的内部状态。

导出内容不含账号标识、CloudKit 元数据、排队中的变更、冲突记录和日历绑定。

13已发布形态与目标模型的差距

当前版本：B1–B6 已进入 iPhone，C1/C2 已进入 Web 本地合约；D1 仍区分本地证据与 live gates。
